像素涂鸦 · 补丁仓库说明
================================================================

这个目录的内容，整个对应 GitHub 上的补丁仓库：

    woa9527/-pixel-patches          （公开的，App 从这边拉更新）


目录里都有什么
----------------------------------------------------------------
    patch.json       ★ 根目录这一份是「指针」—— App 每次检查的就是它
    v1.2/            1.2 这一版的完整内容（patch.json + css/ + js/）
    v1.3/            以后每发一版，就多一个这样的目录

为什么分版本目录，而不是每版一个分支：
    updater.js 里检查更新的地址是写死的，只读根目录的 patch.json；
    但装补丁时会用 patch.json 里的 base 字段去找文件。
    所以根目录那份就是「现在该装哪版」的开关 ——
    发新版只要把指针里的 base 指向 v1.3，旧版本原样留着，
    想回滚把指针指回 v1.2 就行。整个过程不用改代码、不用重新打包 App。


发一个新版本（推荐：一条命令）
----------------------------------------------------------------
1. 先把源码改好（改的是  网页多文件版/  里的文件）

2. 生成这一版的补丁：
       cd 像素涂鸦
       python make-patch.py 1.3 "修了选区拖出边界会绕到对面的 bug"

   它会做两件事：
     · 生成  补丁/v1.3/  （这一版的完整快照）
     · 把    补丁/patch.json  的指针改到 v1.3

3. 推到 GitHub：
       python .workbuddy/push_github.py

4. 等 1–2 分钟让 CDN 同步。


怎么确认发对了
----------------------------------------------------------------
浏览器打开这两个，都要能看到内容：

    https://cdn.jsdelivr.net/gh/woa9527/-pixel-patches@main/patch.json
      ← 应显示 "base" 指向 .../main/v1.3

    https://cdn.jsdelivr.net/gh/woa9527/-pixel-patches@main/v1.3/js/updater.js
      ← 应显示 JS 源码

404 的话，要么还没同步完（再等两分钟），要么目录传错了。


版本号怎么定
----------------------------------------------------------------
随便定，只要比 App 里现在的大就行。比较方式是按点分段比数字：

    1.2  <  1.2.1  <  1.3  <  1.10

注意不是字符串比较，所以 1.10 是比 1.2 大的。


手动传（没有脚本的时候）
----------------------------------------------------------------
GitHub 网页打开仓库 → Add file → Upload files
把 patch.json 和要发的那个版本目录整个拖进去。
注意拖【目录本身】，仓库里要保留 v1.3/css/ 这样的结构，
平铺也能跑，但 patch.json 里那堆路径要跟着改。


万一出了问题
----------------------------------------------------------------
· CDN 拉不到 / 补丁有毛病 → App 自己退回安装包里的内置版本，不会卡住
· 想手动退出在线补丁 → 设置 → 最下面「回到内置版本」
· 同一版补丁崩过一次，App 会记住，不再自动重试
